# DESIGN.md — дизайн-фильтр

Пользователь требует: каждый визуальный результат сначала проходит через DESIGN.md.
Порядок работы:

1. **Прочитай** `references/philosophy.md` (коротко) и при необходимости
   `references/spec.md` (полная спецификация формата). Примеры —
   `references/examples/*.md`.
2. **Напиши DESIGN.md для задачи** рядом с результатом
   (например `presentations/<проект>/DESIGN.md`):
   - YAML front matter: `name`, `colors` (обязательно `primary`), `typography`,
     `rounded`, `spacing`, `components` (ссылки вида `{colors.primary}`).
   - Разделы `##` строго в порядке: Overview → Colors → Typography → Layout →
     Elevation & Depth → Shapes → Components → Do's and Don'ts.
   - В Overview — **конкретный референс**, а не набор прилагательных
     («инвестиционный меморандум петербургского бутик-девелопера»,
     а не «современно, премиально, надёжно»).
   - Для кириллицы выбирай шрифты с кириллицей (Manrope, Inter, IBM Plex Sans,
     Playfair Display, PT Serif, EB Garamond, Golos Text, Onest…).
3. **Проверь**:
   - `npx @google/design.md lint DESIGN.md` — официальный линтер (если разрешён запуск);
   - иначе `python3 .claude/skills/design-md/check_design.py DESIGN.md` — порядок
     разделов, битые ссылки на токены, WCAG-контраст пар компонентов (≥ 4.5:1),
     неиспользуемые цвета. Исправь всё до перехода к вёрстке.
   - Палитру серий графиков дополнительно прогоняй через валидатор скилла dataviz.
4. **Строй результат только из токенов DESIGN.md**: те же hex, шрифты, шкала
   размеров, радиусы, отступы. Никаких «новых» цветов по ходу работы — если нужен
   цвет, сначала добавь его в DESIGN.md и перепроверь.
5. **Коммить DESIGN.md вместе с результатом** — это источник правды для следующих
   правок.
